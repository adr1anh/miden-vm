Construction and complete verification of a flat procedure library in one namespace.<br />Entries contain label commitments, callable keys, and implementation commitments. Keys must<br />be strictly increasing in core::word order. A nonempty library is an ordered binary tree:<br />each round pairs adjacent children and promotes an unpaired final child without padding.<br />The empty library is an empty typed List. Every constructed node's raw hash payload is<br />retained in the advice map under its commitment, for subsequent inspection.<br /><br />Cycles below count raw successful-body VM operations, including callee bodies, generated<br />no-ops, and local-frame allocation/deallocation. They exclude control rows, block framing,<br />operation packing/padding, invocation overhead, and host/chiplet work.<br />


## miden::core::sys::environment::library
| Procedure | Description |
| ----------- | ------------- |
| create | Constructs a library and checks every supplied callable key against its label and namespace.<br /><br />Input:  [NAMESPACE, entries_ptr, count, scratch_ptr, ...]<br />Output: [ROOT, ...]<br /><br />Each entry occupies twelve Felts: [LABEL, KEY, IMPLEMENTATION], all in word element order.<br />Entries must have strictly increasing KEYs, preventing duplicate keys in this library.<br />scratch_ptr reserves count words and is overwritten; entries are preserved. Both pointers<br />must be word-aligned u32s, both exclusive end pointers must fit in u32, and their ranges<br />must not overlap. Empty ranges do not overlap. Unwritten input memory reads as zero.<br />Neither this procedure nor its inlined helpers allocate local frames. Input and scratch<br />may occupy caller locals or higher addresses, provided their ranges remain disjoint.<br /><br />This checks the complete flat library, not any enclosing environment. The caller must supply<br />its intended namespace and authorize ROOT before using it as an execution environment.<br />count must not exceed 65536. Small trees are constructed directly with mtree_merge; larger<br />trees use a bounded handler to prepare an untrusted root and witnesses. MASM verifies every<br />larger-tree leaf at its canonical position with mtree_verify; the complete frontier authenticates<br />the exact library shape and leaf count. Both paths record native-store and raw-map witnesses.<br />Empty and singleton libraries use direct root checks because Merkle opcodes require depth>0.<br />Namespace, loop cursors, and counts remain on the stack; no local frame is allocated.<br /><br />Cycles: 74 for count=0 and `190 + k` for count=1. For count in 2..=7:<br />`61 + (129 + k)*count + 132*t + R`, where R is 54, 123, 177, 285, 334, 399, respectively.<br />For count>=8: `79 + (155 + k)*count + 127*popcount(count) + 132*t`.<br />Here `k` is 12 for the initial namespace and 23 otherwise.<br />Here `t` is the number of adjacent key pairs whose coordinate 3 is equal, requiring the<br />full-word comparison. `popcount(count)` is the number of perfect frontier blocks.<br /> |
| update_at | Replaces one authenticated leaf in a native binary environment collection.<br />Input: [descriptor_ptr, ROOT, KEY, NAMESPACE, ...]. Output: [NEW_ROOT, ...].<br /><br />The aligned sixteen-Felt descriptor is [LABEL, OLD_IMPLEMENTATION, NEW_IMPLEMENTATION,<br />depth, index, 0, 0]. It must end at or below this procedure's local frame; caller-local<br />descriptors remain supported. depth is in 0..=64, index is a canonical Felt interpreted as<br />an unsigned integer and must fit the selected depth. At depth zero index must be zero.<br /><br />MASM derives KEY from NAMESPACE and LABEL, hashes both typed leaves, and authenticates<br />OLD_IMPLEMENTATION using the old leaf returned by mtree_set. The update opcode verifies<br />the old root and preserves every off-path sibling; no redundant mtree_verify is performed.<br />A singleton is checked and replaced directly because the opcode does not accept depth zero.<br />New internal nodes enter the Merkle store; the new Mast's raw payload enters the advice map.<br /><br />Cycles: `315 + k` at depth zero or `351 + k` at depths 1..=64, including 14 local-frame<br />operations. Here `k` is 12 for the initial namespace and 23 otherwise.<br />The native update's old and new Merkle-path chiplet work grows with depth.<br /> |
| verify | Checks an expected library root against the complete supplied entries and namespace.<br /><br />Input:  [ROOT, NAMESPACE, entries_ptr, count, scratch_ptr, ...]<br />Output: [...]<br /><br />Uses the same memory, ordering, and advice-map contracts as create. ROOT can be supplied<br />as a public input. Every entry is checked, so an omitted, extra, or altered entry fails.<br /><br />Cycles: create's raw body cost + 18 (seven argument-permutation operations and eleven<br />for the final word assertion).<br /> |
